# Test — 전 계층 회귀 게이트 (범용)

프로젝트의 테스트를 **4계층**으로 나눠 한 번에 돌리고, 수치 결과를 **기록된 밴드**에 비교해 판정한다. 핵심 원칙은 프로젝트 무관이고, 실제 명령·시뮬 이름은 각 프로젝트 `docs`(테스트 전략 인덱스)에서 찾는다.

## ⚠ 전수 확인·검증 원칙 (전체 테스트 시 — 표본·생략 금지)

"전체 테스트 진행"은 **등록된 모든 테스트 케이스를 빠짐없이 실행하고, 각각의 결과를 실제로 확인·검증**한다는 뜻이다. 일부만 돌리거나, 돌렸다고 가정하거나, 통과를 추정으로 단정하지 않는다.

1. **전 케이스 실행** — 검증 루틴 문서의 전 계층을 하나도 건너뛰지 않고 돈다. 무거워 오래 걸려도 끝까지 완주시킨다 — 느린 건 생략 사유가 아니다.
2. **각 결과를 눈으로 확인** — 모든 테스트의 끝줄(PASS/FAIL 카운트·밴드 충족·`Tests: N passed`)을 **실제 출력에서 확인**한 뒤 표에 옮긴다. "아마 통과했을 것"으로 채우지 않는다.
3. **검증 = 단순 무크래시가 아니다** — exit 0 이어도 단언이 실제로 PASS인지, 통계형은 밴드 안인지까지 본다. 밴드 밖이면 정량화 → 의도/회귀 판정.
4. **누락이 곧 사고** — 어떤 케이스가 실행 목록에서 빠졌다면(커버리지 감사로 검출), 그 자체가 실패다. 자가치유로 루틴 문서에 넣고 보고에 명시한 뒤 다시 전수 실행.
5. 🔴 **부분 실행으로 커밋하지 않는다** — 목록에 *있는데 안 돌린* 것이 가장 위험하다. 목록은 멀쩡하니 커버리지 감사(위 4)에도 안 걸리고, 커밋 메시지의 검증 줄은 *돌린 것만* 적어서 초록불처럼 보인다.
   - 🔴 **계약을 바꾼 커밋에서는 그 계약을 재는 계층을 반드시 포함**한다(엔진 규칙을 바꿨으면 통합/e2e 까지).
   - ⚠ 실측 사고(농구명가 EC-040 · 2026-08-31~09-01): 경기 중 체력을 *평평한 값 → 출전 시간 비례* 로 바꾼 뒤 **`test:api` 를 이틀 동안 한 번도 안 돌렸다.** 그 사이 커밋 셋이 나갔다. 다시 돌리자 **둘**이 걸렸다 — ① 낡은 단언(평평한 값 시절의 부등식) ② 🔴 **진짜 회귀**: 서버만 상대 벤치를 넘겨 **클라 재생이 서버와 갈라지고 있었다**(45:55 vs 42:53). 그 갈라짐을 감지하라고 만든 가드가 바로 그 안 돌린 스위트에 있었다.
   - 🔴 교훈: **검증 목록에서 한 칸을 빼면 그 칸이 지키던 계약이 조용히 죽는다.** 값이 늙는 것(세는 법 · `DOC_SYSTEM` §2)과 같은 종류인데, 여기서는 **안 돌린 스위트가 늙는다.**

## 4계층 모델
1. **엔진/로직 단위** — 순수 계산식·상태전이·계약(I/O 없는 함수). 빠르고 결정적. 통계형은 표본 명시.
2. **화면/UI 단위** — 컴포넌트·훅 렌더/상호작용/표시 규칙. 외부 IO는 mock, 요청 함수는 인자·횟수 단언.
3. **통합** — 여러 모듈을 한 흐름에서 조합 + 전 과정 시나리오(end-to-end). 방대하면 **runbook 문서**로 다른 세션이 실행.
4. **메타(test-of-tests)** — 테스트 스위트 *자체*의 사각(보고만 하고 안 쓰는 결과·미배선·미검증)을 정적/구조적으로 강제 점검.

## 단일 기준 — 검증 루틴 문서

전체 실행의 권위는 **프로젝트의 검증 루틴 문서**(예: `docs/README.md`·테스트 전략 §"한 방 실행")다. **명령 목록을 이 스킬에 베껴두지 않는다** — 베끼면 드리프트해서 새 가드가 누락된다(전형 사고). 매번 그 문서를 **읽어서** 거기 적힌 그대로 돈다.

## 실행 전 — 가드 커버리지 감사 (드리프트·누락 차단) ⚠ 핵심
루틴을 돌리기 **전에**, 검증 루틴 문서가 실재 가드를 전부 덮는지 점검:
1. 루틴 문서의 실행 블록을 Read(권위 목록).
2. 테스트 디렉토리의 실재 가드 sim/스펙 전부 나열.
3. 메타 가드(test-of-tests)가 "가드"로 분류하는 것이 루틴에 **전부 포함**됐나 대조. 누락 = 사고 → 루틴 문서에 추가(자가치유)하고 보고에 명시한 뒤 진행. (메타 가드는 *형식*만, 이 감사는 *루틴이 실제로 부르나*를 본다 — 다른 사각.)

## 실행 순서
1. 타입체크(0건) → 2. 엔진 단위(빠름) → 3. 화면 단위 → 4. 통합(전 과정) → 5. 메타.
- 부분 변경이면 **영향 계층만**: "무엇을 만졌나 → 무엇을 도나" 매핑 표(프로젝트 docs)를 따른다.
- 동시 과부하 주의: UI 단위 다수 + 헤드리스를 함께 돌리면 비동기 렌더 타임아웃 플레이크 가능(부하성 — 단독 재실행으로 회귀 여부 확인).

## 보고 — 판정 표
각 계층 결과를 표 한 장으로(계층 · 명령 · 결과). 끝줄 PASS/FAIL 카운트 또는 밴드 충족 여부를 그대로 옮긴다.

## 판정 — 밴드 + 오차범위 (눈대중 금지)
- 결과는 **밴드(기대 범위)** 안이면 PASS, 벗어나면 WARN/회귀 의심.
- 두 오차를 구분: **표본오차**(같은 코드 재실행 시 RNG 폭, 신뢰구간 ±)와 **변경 편차**(변경 전 밴드 대비 측정값 차이). 편차가 표본오차 안이면 노이즈, 밴드 밖이면 ① 의도 → 밴드+베이스라인 갱신 ② 의도 밖 → 회귀.
- 가능하면 **베이스라인을 기계 판독 파일**로 두고 측정값과의 델타를 도구로 산출(눈대중 제거).

## 통계 3룰 (수치 다룰 때)
1. **충분한 표본** — 빠른 단위는 큰 N, 느린 풀시뮬은 현실 최대 + 표본수·오차 명기.
2. **숫자엔 항상 함께**: 표본수(n)·측정일·어떤 시뮬·어떤 로직.
3. **로직 변경 시 기존 통계 전부 처리** — 즉시 재측정 갱신 또는 "재검증 필요(로직 변경 날짜)" 마킹.

## 돌리는 중 새 케이스가 나오면 — 반드시 문서화 (자가치유)
**(A) 기존 테스트가 깨졌다 = 버그 발견** → 3종 기록: ① 현재 오류(증상/원인/수정/재검증) ② 사각 분석("왜 기존 테스트가 못 잡았나" 분류) ③ 형제 사냥(같은 근본원인의 다른 모듈 점검). 사각 닫는 케이스를 **추가해야 수정 완료**.
**(B) 새 가드를 만들었다** → 3종: ① A/B 자가검증(깬 입력 FAIL·클린 0 — 허위 오라클 차단) ② 케이스 문서 등록(계약·엣지·메타 문서) ③ **검증 루틴 문서에 명령 추가** = 자가치유(다음 전체 테스트에서 자동으로 돈다). 안 넣으면 다음번 §커버리지 감사가 잡지만 그 자리서 넣는 게 정석.

## 엣지케이스 사냥 렌즈 (우선순위)
① 시간차(행동 시작↔결과 확정 사이 상태 변화) → ② 자원 경합(하나를 둘이 점유) → ③ 생애 경계(마지막 1건·재시작·전이) → ④ 의미 정합(크래시 안 나는데 틀림·보고만 하고 미배선) → ⑤ id/동시성 충돌. 앞쪽일수록 광맥이 굵다.
