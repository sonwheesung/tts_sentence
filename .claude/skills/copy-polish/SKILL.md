# copy-polish — 문구 다듬기를 맡기고, 돌아온 것을 믿지 않는다

> **왜 스킬인가**: "ChatGPT에 붙여넣고 받아오기"는 누구나 한다. 사고는 거기서 안 난다.
> 사고는 **돌아온 결과를 그대로 반영할 때** 난다 — 법정 고지의 사실이 바뀌고, `{{count}}` 가
> 사라지고, 탭 라벨이 길어져 잘리고, 한국어만 고쳐 나머지 14개 언어가 갈라진다.
> 이 스킬의 8할은 **보내기 전 제약 추출**과 **받은 뒤 기계 검증**이다.
>
> **경계**: 번역이 *있느냐*(키 누락·드리프트)는 커버리지 가드. 번역 *길이*가 화면을 깨는 것은
> [`i18n-layout-audit`](../i18n-layout-audit/SKILL.md). 이건 **문장 자체가 사람 말인가**이다.

---

## 0. 먼저 인정할 것 — 이건 모델이 사람보다 못하는 일이다

에이전트가 쓴 한국어는 **문법은 맞는데 아무도 그렇게 말하지 않는** 경우가 많다.
*"나가는 것:"* · *"~고는 말씀드릴 수 없어요"* · *"처리해요"* 같은 것들이다.
사용자가 *"너가 하면 어색해"* 라고 하면 그건 취향 문제가 아니라 **관측된 사실**이다 — 반박하지 말고 맡긴다.

🔴 **다만 맡기는 대상이 바꾸면 안 되는 것을 모른다.** 그래서 이 순서다.

---

## 1. 보내기 전 — **바꾸면 안 되는 것**을 먼저 뽑는다

프로젝트마다 다르다. 아래 다섯 축을 **문서에서 찾아** 프롬프트에 적는다. 기억으로 쓰지 않는다.

| 축 | 어디서 찾나 | 예 |
|---|---|---|
| **A. 법정 고지의 *사실*** | `docs/*_SYSTEM.md`·`CLAUDE.md` 의 고지 규약 | *"AI 는 「저장하지 않는다」는 되고 「볼 수 없다」는 안 된다"* |
| **B. 자리표시자** | 문자열 자체 | `{{count}}` · `%s` · `{0}` |
| **C. 고유 용어** | 제품 용어집·`CLAUDE.md` | 일기 한 편 = *"조각"*. 번역·의역 금지 |
| **D. 길이 상한** | 레이아웃 규약 | 탭 라벨·버튼은 짧게. 독일어가 2배로 늘어난다 |
| **E. 말투** | 기존 문구에서 귀납 | 해요체 / 담백 / 느낌표 없음 |

**A 를 찾는 법** — 고지 규약은 대개 *"(O) / (X)"* 형태로 문서에 박혀 있다:

```bash
grep -rn "(O)\|(X)\|절대\|쓰지 않는다\|라고 쓰지" docs/*.md CLAUDE.md | grep -v "~~"
```

🔴 **A 를 안 적으면 LLM 이 반드시 건드린다.** 법정 문구는 어색하게 들리도록 일부러 쓴 것이 많아
(정확성이 자연스러움을 이긴 자리) LLM 이 "개선 대상"으로 인식한다.

⚠ **금지와 요구를 구분한다.** *"「볼 수 없다」고 쓰지 마라"* 는 **금지**이지
*"「볼 수 없다고 보장 못 한다」고 써라"* 는 **요구가 아니다.** 이 둘을 섞으면
LLM 이 이중부정을 만들어 오고, 그게 원래 어색함보다 나쁘다(실측 사례 §5).

## 2. 넘기는 방법 — **붙여넣지 말고 파일로**

```bash
# 중첩 JSON 을 평탄화해 한 파일로 (키를 보존해야 되돌릴 수 있다)
node -e "
const fs=require('fs'); const src=require('./locales/ko.json'); const out={};
(function w(o,p){for(const[k,v]of Object.entries(o)){const q=p?p+'.'+k:k;
  if(typeof v==='string')out[q]=v; else if(v&&typeof v==='object')w(v,q);}})(src,'');
fs.writeFileSync('/tmp/strings.json', JSON.stringify(out,null,1));
console.log(Object.keys(out).length,'개');
"
```

그다음 브라우저에서 **파일 첨부**(`file_upload`)한다. 수천 자를 `computer.type` 으로 치지 않는다.

### 🔴 겪은 함정 셋 (2026-09-08 조각, 전부 실측)

| | |
|---|---|
| **첫 줄바꿈이 전송이다** | `computer.type` 의 `\n` 이 Enter 로 먹혀 **제약을 적기 전에 첫 메시지가 나갔다.** → 제약을 **먼저** 치고 마지막에 Enter. 또는 한 번에 한 문단씩 |
| **`innerText` 는 코드블록을 자른다** | 9,026자 응답이 2,643자로 잘려 `JSON.parse` 가 깨졌다. → **`textContent`** 를 쓴다 |
| **탭 포커스가 새어나간다** | 배치 중간에 `Couldn't determine which page` — 매 배치 첫 동작을 **입력창 클릭**으로 시작한다 |

## 3. 프롬프트 뼈대

```
첨부 JSON 은 <플랫폼> 앱 <이름>의 <언어> UI 문구 전체(N개)입니다.
번역투가 난 어색한 표현을 자연스럽게 다듬어 주세요.

[말투]  <E 축 — 기존 문구에서 뽑은 2~3줄>
[고유 용어]  <C 축 — 바꾸면 안 되는 단어>

[반드시]
1. 키는 그대로. 값만 고칩니다
2. <B 축> 자리표시자는 개수·철자 그대로
3. 길이를 키우지 마세요. <D 축 — 특히 짧아야 하는 키>

[손대면 안 되는 사실]   ← A 축. 여기가 이 프롬프트의 핵심이다
<규약을 그대로 옮겨 적는다. "문장은 다듬되 이 사실은 유지" 라고 명시>

[지금 가장 어색한 곳]  <사용자가 짚은 문자열 키를 그대로>

[출력]  고친 것만 JSON(키: 새 값) + 주요 변경 이유 한 줄씩
```

🟢 **"고친 것만"** 이 중요하다 — 전체를 받으면 안 고친 것까지 미묘하게 달라져 diff 가 못 쓰게 된다.

## 4. 🔴 받은 뒤 — **기계로 검사하고 나서** 반영한다

사람 눈으로 171개를 못 본다. 아래를 **먼저** 돌린다.

```bash
node -e "
const before=require('/tmp/strings.json');       // 보낸 것
const after=require('/tmp/polished.json');       // 받은 것
const ph=s=>(s.match(/{{[^}]+}}|%[sd]|{\d+}/g)||[]).sort().join(',');
let bad=0;
for(const [k,v] of Object.entries(after)){
  if(!(k in before)){ console.log('NEW KEY  '+k); bad++; continue; }
  if(ph(before[k])!==ph(after[k])) { console.log('PLACEHOLDER  '+k+'\n   전 '+ph(before[k])+'\n   후 '+ph(after[k])); bad++; }
  if(after[k].length > before[k].length*1.3 && before[k].length>6)
    console.log('LONGER   '+k+'  '+before[k].length+' -> '+after[k].length);
}
console.log('바뀐 키', Object.keys(after).length, '· 문제', bad);
"
```

그다음 **사람이 봐야만 하는 것** 둘:

1. **A 축(법정 사실)에 걸리는 키만 뽑아 눈으로 읽는다.**
   ```bash
   node -e "const a=require('/tmp/polished.json');
   for(const[k,v] of Object.entries(a)) if(/^(legal|consent|privacy|subscribe|backup|ai)/i.test(k)) console.log(k+'\n   '+v+'\n');"
   ```
   금지 표현이 되살아났는지, 빠진 항목(사업자명·기간·연락처)이 없는지 본다.

2. **말투가 통째로 이동했는지.** LLM 은 "자연스럽게"를 **격식체로** 해석하는 경향이 있다
   (`쓰실 수 있어요` → `사용할 수 있어요`). 그건 자연스러워진 게 아니라 **다른 앱이 된 것**이다.
   → 한 번 더 시킨다: *"기존의 부드러운 말투를 유지하고 한자어를 줄여라"* + 구체적 대비 예시 3개.

## 5. 실측 사례 — 제약을 줘도 이렇게 나온다 (2026-09-08 조각)

원문(어색함을 지적받은 문장):
```
• 저희는 그 내용을 저장하지 않아요. 다만 요약을 만드는 그 순간에는 내용이
  저희 서버를 지나가요 — "볼 수 없다"고는 말씀드릴 수 없어요
```

1차 결과 — **사실은 더 정확해졌는데 어색함은 그대로**:
```
• …암호화되지 않은 상태로 저희 서버를 거쳐 AI 사업자에게 전송돼요.
  서버를 거치는 동안 내용을 볼 수 없다고 보장할 수 없어요.
```
🔴 *"볼 수 없다고 **보장할 수 없어요**"* — **이중부정**. 규약(*"「볼 수 없다」고 쓰지 마라"*)을
"안 보인다고 부정하라"로 오해한 것이다. 지적한 어색함이 형태만 바꿔 살아남았다.

→ **금지를 요구로 착각하게 두지 않는다.** *"단정하지만 않으면 된다. 그 문장은 통째로 빼라"* 로
   다시 시킨다. 앞 문장에 사실이 있으면 **고지는 이미 충족**이다.

## 6. 반영 — 한 언어만 고치면 갈라진다

🔴 **원본 언어를 고쳤으면 나머지 언어도 같이 고친다.** 키 커버리지 검사는 *존재*만 보므로
한국어만 바꿔도 **초록불이다** — 그리고 나머지 언어는 옛 문장을 그대로 들고 남는다.

```
1. 원본 언어 반영 → 화면에서 눈으로 1회
2. 나머지 언어: 바뀐 키만 뽑아 각 언어로 재번역
3. 커버리지·자리표시자 가드 재실행
4. 레이아웃은 i18n-layout-audit 으로 (길어진 문자열이 있으면 필수)
```

⚠ **법정 문구를 고쳤으면** 그 언어들의 법무 문서(처리방침·약관)와 **같은 사실을 말하는지** 본다.
화면 문구만 부드럽게 고치고 처리방침이 옛 문장이면 그 자리에서 어긋난다.

---

## 7. 산출물

① 보낸 파일 · 받은 파일(둘 다 남긴다 — diff 가 유일한 증거다)
② 기계 검사 결과(자리표시자·새 키·길이 증가)
③ A 축 키의 사람 확인 기록
④ 반영한 언어 수 · 남은 언어

⚠ **원본과 결과 파일을 지우지 않는다.** *"왜 이 문장이 이렇게 됐나"* 를 나중에 물을 때
diff 가 없으면 답할 수 없고, LLM 은 같은 입력에 같은 출력을 주지 않는다.
